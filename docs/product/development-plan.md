# 信扬供应链服务平台开发计划

## 1. 交付策略

正式一期整体上线，研发按模块逐步完成。先交付覆盖全部一期功能的全栈 Demo，经确认后进行生产化差距评估、真实接口接入、安全加固、完整测试和一次性上线。

## 2. 建议团队

| 角色 | 建议人数 | 主要职责 |
| --- | --- | --- |
| 产品经理 | 1 | PRD、流程、验收和变更管理 |
| UI/UX | 1 | 门户设计、组件规范、可用性检查 |
| 前端工程师 | 2 | 门户、管理端、自动化测试 |
| 后端工程师 | 3 | 业务模块、工作流、权限、集成 |
| 测试工程师 | 2 | 功能、接口、自动化、性能和安全测试 |
| DevOps | 0.5～1 | 环境、流水线、部署和监控 |
| 架构/技术负责人 | 1 | 架构、数据、接口和质量门禁 |

## 3. Demo 研发批次

| 批次 | 建议周期 | 范围 | 可验收结果 |
| --- | --- | --- | --- |
| D0 设计与基座 | 1 周 | 项目结构、主题、认证、权限骨架、模拟适配器、数据重置 | 九类账号可登录，应用可启动 |
| D1 门户内容 | 1～2 周 | 首页、品牌、公告、案例、资质、双语 | 门户内容发布闭环 |
| D2 产品与方案 | 2 周 | 分类参数、产品、批量导入、场景、方案、对比、规则推荐、搜索 | 选型和标准方案购买入口 |
| D3 企业与需求 | 2 周 | 注册、主子账号、资质、联系人、线索、需求、协作、SLA | 定制方案确认闭环 |
| D4 交易与履约 | 2 周 | 购物车、价格库存、拆单、客户/销售订单、审核、物流、评价 | 直接采购和履约闭环 |
| D5 计划与平台 | 1～2 周 | 需求计划、额度、Flowable、消息、Dify、权限扩展、导入导出 | 计划及平台管理闭环 |
| D6 集成验收 | 1 周 | 全流程、异常、视觉、性能、安全、数据重置 | 可供用户验收的 Demo |

按 2 名前端、3 名后端、2 名测试并行估算，Demo 建议 10～12 周；单人或小团队需相应延长。该估算不含需求范围大幅变化和真实外部接口联调。

## 4. 正式开发阶段

1. Demo 差距评估：确认保留、重构和废弃代码。
2. 接口设计：完成 XTS、CRM、Dify、物流、邮件、内部通讯和 SSO 契约。
3. 生产化开发：事务、一致性、幂等、安全、审计、容错和运维能力。
4. 数据准备：主数据清洗、双语内容、初始化字典和迁移演练。
5. 系统联调：按接口适配器逐项切换模拟实现。
6. 测试：SIT、UAT、性能、安全、容灾和上线演练。
7. 整体上线：冻结变更、全量部署、数据校验、业务验收和观察期。

正式开发建议 16～22 周，需在接口、环境、安全规范和人员确定后重新估算。

## 5. 质量门禁

- 每个模块必须有自动化单元与集成测试。
- 每个研发批次必须提供可运行增量和对应验收记录。
- 合并前通过代码审查、静态扫描、依赖漏洞扫描和测试。
- P0/P1 缺陷清零后进入 Demo 验收或正式 UAT。
- 正式上线前完成性能、安全、备份恢复和回滚演练。

## 6. 依赖输入

- 正式项目启动前：SpringBlade 固定版本、开发/测试/生产环境规范。
- 接口开发前：XTS、CRM、Dify、邮件、通讯、物流、SSO 文档和测试环境。
- UAT 前：脱敏产品、方案、客户、订单、计划及双语内容。
- 上线前：运营主体、合同主体、域名、证书、备案、等保和国产化结论。

## 7. 变更管理

- 澄清台账是需求决策源，新增或修改需求必须记录编号、理由、影响和决策。
- PRD 版本冻结后，变更需评估范围、工期、测试和上线影响。
- Demo 调整不自动等同于正式生产需求，必须回写 PRD 和验收标准。
