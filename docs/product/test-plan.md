# 信扬供应链服务平台一期测试方案

## 1. 目标

验证全部一期功能、九类角色、关键状态机、数据隔离、模拟外部接口、双语体验和性能基线，确保 Demo 可稳定演示，并为正式开发建立可复用测试资产。

## 2. 测试层级

| 层级 | 范围 | 建议工具 | 准入/准出 |
| --- | --- | --- | --- |
| 单元测试 | 价格、库存、拆单、额度、权限、状态机、推荐评分 | JUnit 5、Vitest | 核心规则分支全覆盖 |
| 组件测试 | Controller、应用服务、MyBatis、Flowable、Redis、文件 | Spring Boot Test、Testcontainers | 模块接口和事务通过 |
| 契约测试 | XTS、CRM、Dify、物流、消息适配器 | WireMock/OpenAPI 校验 | Mock 与契约一致 |
| 前端测试 | 表单、权限、状态、国际化、组件交互 | Vitest、Vue Test Utils | 关键组件通过 |
| 端到端测试 | 九类角色的四条主流程 | Playwright | P0/P1 场景通过 |
| 性能测试 | 浏览、搜索、登录、提交需求、订单查询 | k6/JMeter | 满足 50 RPS 与 P95 指标 |
| 安全测试 | 认证、越权、上传、导出、敏感信息 | OWASP ZAP、依赖扫描、人工检查 | 无高危问题 |
| 视觉测试 | 1440/1280/1024、双语、长文本 | Playwright 截图 | 无遮挡、溢出和关键差异 |

## 3. 测试环境

- Demo 环境：单机容器化，模拟 XTS、CRM、Dify、物流、邮件和内部通讯。
- 数据：九类角色账号、三类企业状态、至少 30 产品、12 方案、6 场景、10 工单、10 订单、6 需求计划。
- 浏览器：Chrome 最新稳定版为主，Edge 最新稳定版兼容。
- 每轮验收前执行演示数据重置并记录数据版本。

## 4. 端到端场景

1. 访客搜索产品，查看公开价，登录后继续购买并完成订单提交。
2. 企业子账号提交订单，主账号内部确认，平台审核并模拟履约和评价。
3. 客户提交定制需求，运营分派，工程师提交两个版本，客户确认并转订单。
4. 客户使用规则匹配和方案对比后直接购买标准方案。
5. 销售代客创建协议价外订单，完成价格审批、客户确认和平台审核。
6. 产品公司导入需求计划，触发超额特殊审批，模拟执行回传和额度释放。
7. 运营批量导入产品，修复错误记录，审核发布并在门户搜索到新产品。
8. 管理员修改品牌、公告、权限、流程和 Dify 配置，验证即时生效与审计。

## 5. 重点边界

- 重复企业注册、资质过期、账号锁定、双因素认证。
- 价格变化、库存变化、下架、最小起订量、方案必选项。
- 订单非法状态转换、撤回、驳回重提、取消、多次发货。
- 工单 SLA 超时、重复线索、无匹配方案、方案版本并发确认。
- 超额计划、额度释放、跨产品公司越权。
- Dify、XTS、CRM、物流和消息适配器超时、失败、重复回调。
- 导入非法文件、超限附件、公式注入、导出越权和下载过期。
- 中文/英文切换、缺失翻译、长英文文本和时区显示。

## 6. 安全检查

- API Key、密码、验证码和令牌不得进入日志或前端响应。
- 上传文件校验扩展名、MIME、大小和病毒扫描接口；对象存储使用非公开桶和临时授权地址。
- 每个查询、搜索和导出均验证企业、数据和字段权限。
- 防止 SQL 注入、XSS、CSRF、SSRF、路径穿越和 Excel 公式注入。
- 登录、权限、价格、审核、发布、导入导出和系统配置必须审计。

## 7. 性能模型

| 事务 | 流量比例 | P95 目标 |
| --- | --- | --- |
| 首页/产品/方案浏览 | 45% | ≤2 秒 |
| 搜索筛选 | 25% | ≤3 秒 |
| 登录与用户信息 | 10% | ≤2 秒 |
| 需求和订单查询 | 15% | ≤2 秒 |
| 提交类操作 | 5% | ≤2 秒，不含异步处理 |

持续 30 分钟达到 50 RPS，错误率≤1%，数据库连接、JVM、CPU、内存和慢查询无持续恶化。

## 8. 缺陷与验收

- P0：阻塞主流程、数据泄露、金额/额度错误。必须全部关闭。
- P1：重要功能错误或无替代路径。必须全部关闭。
- P2：非核心功能错误且有替代路径。经评审可带限量遗留。
- P3：视觉或文案问题。纳入修复清单，不影响演示时可评审接受。

Demo 验收必须满足：构建和自动化测试通过；八条端到端场景通过；无 P0/P1；权限隔离、安全基线、性能和数据重置验证通过。
