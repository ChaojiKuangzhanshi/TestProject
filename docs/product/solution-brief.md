# 方案简报：信扬供应链服务平台

## 问题概述

现有产品、方案、需求、订单与客户沟通分散在线下及多个系统中，企业客户难以自助选型、在线协作并持续跟踪订单。内部运营、销售和工程师也缺少统一的内容发布、需求分派、审批和留痕入口。

## 方案

建设统一 B2B 供应链服务平台。访客可浏览价格、产品、场景和方案；企业客户可直接购买产品或标准方案，也可提交定制需求并在线完成方案确认；产品公司可提交需求计划；内部人员在统一管理端完成内容运营、销售跟进、方案协作、订单审核和系统配置。

## 核心能力

1. **产品与方案采购：** 多维检索、规则推荐、方案对比、组合购物车和订单履约。
2. **需求与方案协同：** 多入口工单、自动分派、SLA、在线沟通、版本确认和转订单。
3. **企业服务：** 企业注册审核、主子账号、资质、联系人、协议价和企业内订单确认。
4. **运营管理：** 首页、公告、产品、方案、案例、资质、批量导入和多语言内容发布。
5. **平台能力：** SpringBlade 权限、Flowable 工作流、统一消息、Dify 接入、审计和外部系统适配。

## 成功指标

| 指标 | 基线 | 一期目标 |
| --- | --- | --- |
| 产品/方案线上可检索率 | 未建立 | 100% 已发布数据可检索 |
| 线上需求闭环率 | 未建立 | ≥90% 工单在线留痕并结案 |
| 订单状态可视率 | 未建立 | 100% 有效订单展示当前状态 |
| 需求首次响应 SLA 达标率 | 未建立 | ≥95% |
| 核心页面响应 | 未建立 | 95% ≤2 秒 |
| 全局搜索响应 | 未建立 | 95% ≤3 秒 |

## 主要取舍

| 取舍 | 原因 |
| --- | --- |
| 采用模块化单体而非微服务 | 当前规模为 30 人同时在线、50 RPS，优先降低研发和运维复杂度 |
| 一期规则匹配而非训练 AI 模型 | 保证可解释性，并等待真实选型数据积累 |
| Dify 负责智能问答 | 避免重复建设知识库和模型编排能力 |
| Demo 使用模拟外部系统 | 先验证全流程体验，不受接口准备度阻塞 |
| 一期整体上线但模块化研发 | 保持统一业务闭环，同时便于阶段性交付和测试 |

## 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 全部一期范围较大 | Demo 与正式开发周期增加 | 按业务域分批完成，统一集成验收 |
| 外部接口未知 | 正式集成返工 | 统一适配层、模拟契约、正式开发前接口评审 |
| 开源 SpringBlade 能力差异 | 权限和流程需要扩展 | 固定版本并建立能力差距清单 |
| 运营内容和样例数据不足 | Demo 真实感不足 | 使用可替换的脱敏演示数据集 |

## 下一步

1. 以 PRD、用户故事和验收标准固定一期范围。
2. 完成 Demo 信息架构、视觉规范和数据脚本。
3. 按基础平台、门户内容、交易闭环、协同与集成顺序建设 Demo。
4. Demo 验收后补齐真实接口、部署和安全输入，形成正式开发基线。
