# PRD：信扬供应链服务平台一期

## 1. 概述

### 1.1 问题

企业客户当前难以从统一入口完成产品/方案选型、需求沟通、采购和履约跟踪。内部产品、客户、需求、订单及通知分散在多个系统与线下沟通中，状态不透明、数据重复、过程缺少留痕。

### 1.2 解决方案

建设公网可访问的 B2B 客户门户和统一管理端，支持产品及标准方案直接购买、定制需求协同、销售代客建单、需求计划、订单履约、内容运营和平台配置。Demo 覆盖全部一期能力，外部系统使用模拟适配器；确认后再进行生产化开发与真实集成。

### 1.3 目标用户

1. 企业访客
2. 企业主账号管理员
3. 企业采购子账号
4. 产品公司业务人员
5. 平台运营人员
6. 销售人员
7. 方案工程师
8. 订单审核人员
9. 平台系统管理员

客服职责由平台运营人员兼任。

## 2. 目标与指标

### 2.1 产品目标

- 建立从发现产品/方案到下单履约的线上闭环。
- 建立从客户需求到版本化方案确认的协作闭环。
- 建立产品公司需求计划与集采额度的线上闭环。
- 建立内容、权限、流程、消息和审计的统一运营底座。

### 2.2 成功指标

| 指标 | 一期目标 |
| --- | --- |
| 已发布产品/方案可检索率 | 100% |
| 有效订单状态可视率 | 100% |
| 需求工单线上留痕率 | ≥90% |
| 需求首次响应 SLA 达标率 | ≥95% |
| 核心流程审计覆盖率 | 100% |
| 普通页面与接口 P95 | ≤2 秒 |
| 全局搜索 P95 | ≤3 秒 |
| 月度可用性 | 99.9%，计划维护除外 |

### 2.3 非目标

- 一期不提供在线支付、电子签章、在线开票、售后退换货和对账结算。
- 一期不训练专用 AI 推荐或方案分析模型。
- Demo 不连接生产 XTS、CRM、物流、邮件、内部通讯或 SSO。
- Demo 不作为未经改造即可上线的生产系统。

## 3. 产品范围

### 3.1 门户与内容

- FR-001：平台名称、简称、Logo、图标、登录页、客服、页脚、备案和分享信息必须可配置并即时生效。
- FR-002：首页必须支持轮播、业务板块、推荐场景、方案、产品、案例、公告和平台资质的启停、排序、定时、定向、审核、版本与回滚。
- FR-003：案例、企业介绍和平台资质必须支持双语、审核、版本与有效期；未经客户授权的案例不得实名公开。
- FR-004：公告必须支持分类、定向企业/角色、公告栏、站内消息、弹窗、定时发布、已读确认、撤回和归档。

### 3.2 产品、场景与方案

- FR-010：产品必须支持事业部、业务线、物料类型等多维分类，以及按品类配置的参数模板。
- FR-011：XTS 基础字段与 B2B 展示字段必须按字段归属同步，B2B 展示内容不得被同步覆盖。
- FR-012：产品必须经过草稿、审核、发布、上下架和版本化流程；已下架产品不得搜索或结算，历史订单保留快照。
- FR-013：产品必须支持 Excel 批量数据和 ZIP 附件导入，先校验后生成草稿，并提供错误报告。
- FR-014：场景、方案、产品和案例必须支持多对多关联。
- FR-015：方案版本必须支持必选、可选和替代产品、默认数量、独立价格、有效期、上下架和直接购买。
- FR-016：用户必须能选择 2～3 个方案对比价格、场景、参数、产品构成、库存和交期，并从结果咨询或购买。
- FR-017：规则匹配必须按必选条件过滤，并结合匹配度、库存、价格和运营权重排序，显示推荐原因；无结果时转需求工单。

### 3.3 企业、账号与联系人

- FR-020：企业注册必须以统一社会信用代码去重，验证手机/邮箱并提交营业执照，经运营审核后创建主账号。
- FR-021：企业主账号必须能管理子账号、功能权限、本人/企业数据范围和订单内部确认规则。
- FR-022：企业资质必须支持类型配置、审核、驳回重提、版本、到期提醒和可配置的过期下单限制。
- FR-023：联系人必须支持多类型、企业共享、默认联系人、通知订阅、验证、脱敏和停用。
- FR-024：系统必须支持用户名/手机号登录、手机/邮箱找回、错误锁定、密码历史、安全日志和双因素认证。

### 3.4 价格、购物车与结算

- FR-030：访客必须能查看公开价；登录企业优先看到企业协议价，并明确价格类型。
- FR-031：购买动作必须要求登录，成功后返回原产品/方案并保留上下文。
- FR-032：方案价格默认为物料合计，可配置方案优惠价；定制方案在报价确认后转订单。
- FR-033：购物车必须按账号隔离，保留方案组合，可调整可选项，必选项不可删除。
- FR-034：系统必须按销售主体、仓库、币种拆单；一期默认人民币。
- FR-035：结算前必须复核价格、库存、上下架和最小起订量；变价需确认，缺货转需求/询单。
- FR-036：结算必须支持企业地址簿、联系人、交付日期、分批交付、备注和开票需求。

### 3.5 需求、方案协同与线索

- FR-040：需求必须可从空白、产品、方案、对比和缺货入口发起并保留来源。
- FR-041：需求支持草稿、结构化参数、联系人、预算、交期及受控附件；访客提交前登录且保留内容。
- FR-042：需求必须按事业部、品类、区域和客户归属推荐负责人，由运营确认；支持转派、协办、升级和 SLA。
- FR-043：需求工单必须支持参与人会话、附件、参数修订、只读方案版本、差异对比及客户确认。
- FR-044：已确认方案修改时必须新建版本并重新确认。
- FR-045：主动咨询、采购意向和方案需求必须生成线索；浏览行为不得自动生成线索。
- FR-046：线索必须去重、分派、关联后续工单/订单，并向客户展示简化状态。

### 3.6 订单、履约与评价

- FR-050：客户可从购物车提交订单；销售可为已审核企业创建版本化订单草稿并请求企业主账号确认。
- FR-051：协议价外的销售人工价格必须额外审批。
- FR-052：订单必须遵循待提交、待审核、驳回/待客户确认、生产备货、待发货、已发货、已签收、已完成状态。
- FR-053：订单必须支持驳回重提、审核中撤回、客户确认和发货前取消申请。
- FR-054：一个订单必须支持多次发货和商品级已发、待发、签收数量，以及物流节点与异常提示。
- FR-055：订单签收后必须支持质量、交付、服务三项 1～5 分评价、文字、图片、一次修改和运营回复；低分触发跟进。

### 3.7 需求计划

- FR-060：产品公司业务人员必须能按月/季度在线创建或 Excel 导入需求计划。
- FR-061：计划必须校验集采额度，普通计划走标准审核，超额计划可进入特殊审批。
- FR-062：计划批准后必须锁定基线并占用额度；变更生成版本，关闭/减少释放未用额度。
- FR-063：平台必须展示 XTS 返回的计划量、执行量和剩余量，并隔离不同产品公司数据。

### 3.8 平台能力

- FR-070：权限必须覆盖菜单、按钮、接口、数据、字段、跨组织限时授权、复制、转移和审计。
- FR-071：Flowable 必须支持可视化流程、顺序、条件、并行会签、驳回、撤回、转办、版本和受控业务动作。
- FR-072：消息中心必须支持站内消息，以及可插拔邮件/内部通讯适配器、模板、重试和已读确认。
- FR-073：平台必须管理 Dify 地址、应用 ID、密钥、超时、启停和欢迎语，通过后端代理调用，故障时转留言。
- FR-074：全局检索必须覆盖公开内容及授权的企业业务数据，并支持模糊、筛选、高亮和排序。
- FR-075：导入导出必须执行模板校验、异步任务、字段/数据权限、脱敏、限时下载和审计。
- FR-076：门户和管理端必须支持中英文；运营内容英文缺失时回退中文并标记待翻译。

## 4. 关键边界与异常

| 场景 | 期望行为 |
| --- | --- |
| 访客购买 | 跳转登录，登录后回到原商品/方案 |
| 价格变化 | 结算阻断，显示新旧价格并要求确认 |
| 商品缺货 | 不生成普通订单，允许转需求/询单 |
| 产品下架 | 搜索隐藏，购物车失效提示，历史快照保留 |
| Dify 不可用 | 显示降级提示并转留言线索 |
| XTS 同步失败 | 本地业务保留，记录失败并允许重试 |
| 导入部分错误 | 不写入错误记录，提供行级错误报告 |
| 权限变更 | 立即影响新请求，记录变更前后值 |
| 运行中流程遇新版本 | 继续使用启动时流程版本 |

## 5. 体验与视觉

- 门户采用工业 B2B 高信息密度布局，主色为信扬红，蓝灰用于流程和技术信息。
- 首页突出全局搜索、产品分类、解决方案、推荐商品、平台能力和信任背书。
- 管理端沿用 SpringBlade/Saber 默认布局与交互。
- 桌面端优先，支持 1440、1280 和最小 1024 像素宽度；门户补充移动端基本适配。
- 重要表单支持草稿、明确校验、可恢复错误和操作反馈。

## 6. 技术约束

- 架构：SpringBlade Boot 模块化单体，保留服务拆分边界。
- 后端：Java 21、Spring Boot、MyBatis-Plus、Flowable。
- 前端：Vue 3、TypeScript、Element Plus；门户与管理端独立应用。
- 数据：MySQL 8、Redis、MinIO。
- 集成：XTS、CRM、Dify、物流、邮件、内部通讯统一适配层。
- Demo：所有外部系统使用模拟实现，数据可一键恢复。
- 规模：100 企业、500 用户、1,000 产品、200 方案、日订单 50、在线 30、峰值 50 RPS、文件 100 GB。
