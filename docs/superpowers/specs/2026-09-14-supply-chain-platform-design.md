# 信扬供应链服务平台总体设计规格

## 1. 设计目标

交付覆盖全部一期功能的可运行全栈 Demo，并使核心模块可在 Demo 确认后进入正式生产化开发。正式一期采用整体上线策略，研发按模块推进。

## 2. 体验设计

门户端参考震坤行与找钢网的工业 B2B 信息结构：顶部品牌与全局搜索、品类导航、场景/方案入口、商品陈列、行业服务区、案例与企业背书。视觉采用信扬红为主色，蓝灰用于技术信息和流程状态，白底高密度布局兼顾采购效率。

管理端使用 SpringBlade/Saber 默认结构，业务菜单按工作台、内容、产品方案、客户、需求、订单、计划、消息、流程、系统配置组织。

门户端与管理端均支持中英文；所有品牌素材和门户名称由管理端配置。

## 3. 系统结构

```text
客户门户 Vue 3       管理端 Vue 3/Saber
        \             /
         SpringBlade Boot API
  认证与权限 | 内容 | 产品方案 | 需求 | 订单 | 计划
  工作流 | 消息 | 搜索 | 文件 | 配置 | 审计
                 |
     XTS/CRM/Dify/物流/邮件适配层
                 |
       MySQL 8 | Redis | MinIO
```

采用模块化单体，每个业务模块拥有明确应用服务和数据表边界。模块间通过应用接口或领域事件交互，不直接跨模块修改数据。外部系统统一经过适配层，Demo 默认启用模拟实现。

## 4. 业务模块

### 4.1 身份、企业和权限

- 九类角色和企业级数据隔离。
- 企业注册、资质审核、主子账号和联系人。
- 菜单、按钮、接口、数据、字段、跨组织限时授权、复制与转移。
- 系统管理员强制双因素认证。

### 4.2 内容、产品和方案

- 首页、公告、案例、平台资质统一内容审核和版本发布。
- XTS 管产品基础字段，B2B 管展示与发布字段。
- 场景、方案、产品、案例多对多；方案版本可直接购买。
- 规则匹配及 2～3 个方案对比。

### 4.3 需求和线索

- 多入口需求表单、附件、匹配、分派和 SLA。
- 工单会话、参数修订、只读方案版本和客户确认。
- 主动咨询生成线索，浏览仅记录分析事件。

### 4.4 购物车、订单和履约

- 公开价和企业协议价；访客可见，购买需登录。
- 产品和方案组合购物车，按主体、仓库、币种拆单。
- 客户订单、销售代客订单、企业内部确认和平台/XTS 审核。
- 多次发货、商品级进度、物流轨迹和订单评价。

### 4.5 需求计划

- 产品公司按月/季度提报，支持 Excel 导入。
- 审核通过后占用集采额度，超额走特殊审批。
- 变更版本、执行量同步和未用额度释放。

### 4.6 平台能力

- Flowable 可视化流程与受控业务动作。
- 站内消息、邮件及内部通讯适配器。
- Dify 配置与后端代理；不可用时转留言。
- 全局检索、批量导入导出、双语、系统配置和审计。

## 5. 核心数据流

### 5.1 直接采购

浏览产品/方案 → 加入购物车 → 登录/企业权限校验 → 价格库存复核 → 自动拆单 → 企业内部确认（可选）→ 平台/XTS 审核 → 履约 → 评价。

### 5.2 定制方案

提交需求 → 规则匹配或人工分派 → 销售/工程师协作 → 提交方案版本 → 客户确认 → 加入购物车 → 订单流程。

### 5.3 需求计划

创建或导入计划 → 额度校验 → 普通/超额审批 → 锁定基线并占用额度 → XTS 执行回传 → 完成/关闭并释放余额。

## 6. 错误与恢复

- 外部系统不可用时保留本地请求、标记同步状态并可重试。
- 价格、库存或商品状态变化时阻断结算并要求客户确认。
- 批量导入先校验，失败记录不写入正式数据，并提供错误报告。
- Dify 不可用时转留言线索。
- 所有失败均返回可理解提示、关联编号和恢复操作。

## 7. 测试设计

- 单元测试覆盖价格、库存、拆单、额度、权限和状态机。
- 集成测试覆盖 Flowable、数据库、文件和模拟适配器。
- 端到端测试按九类角色覆盖直接采购、定制方案、销售建单和需求计划。
- 契约测试保证模拟接口与未来真实接口使用同一数据契约。
- 性能基线为 50 RPS，普通接口 P95≤2 秒，搜索 P95≤3 秒。

## 8. Demo 约束

- Demo 使用模拟外部接口和非生产数据。
- Demo 数据可一键恢复。
- 不实现生产集群、真实 SSO、真实支付和二期能力。
- Demo 通过后先做代码审查和生产化差距评估，再进入正式开发。

## 9. 默认假设与后续输入

- 当前平台名称为“信扬供应链服务平台”，可配置修改。
- 运营主体和合同主体在正式开发前提供。
- XTS、CRM、邮件和内部通讯接口文档在正式集成前提供。
- 备份与恢复按部署环境通用规范执行。
