# Demo 二级页面与按钮交互设计

## 目标

在现有一期交互 Demo 上，将静态按钮和提示型交互补齐为可进入、可操作、可返回的二级页面，同时保持模拟数据、无真实外部写入。

## 页面结构

1. 门户详情层：产品详情、方案详情、方案对比、搜索结果、资讯列表与详情。
2. 企业业务层：需求新建/详情、方案版本对比、结算确认、订单详情/代客建单、计划导入、子账号新建、资质更新、内容编辑/批量上传。
3. 管理工作台：工作台、内容管理、产品与方案、企业客户、需求与线索、订单履约、需求计划、流程与消息、系统管理九个页面。

## 详情链路补充

- 公告：资讯列表 → 公告正文 → 附件下载/收藏 → 返回列表。
- 产品咨询：产品详情 → 咨询表单 → 联系方式确认 → 提交需求。
- 场景购买：方案详情或首页整套购买 → 登录续接 → 配送/发票/金额确认 → 订单审核。
- 新建需求：基础信息、行业场景、预算、参数、附件和联系人 → 校验确认 → 成功页与工单编号。

## 四步表单规范

所有表单统一采用四个真实内容步骤，而非仅切换步骤条：

1. 基础信息：展示当前业务特有的主体字段。
2. 业务补充：展示附件、规则、权限、交付或联系人字段。
3. 确认提交：汇总前两步填写值，并显示权限、状态和数据规则校验结果。
4. 处理结果：显示业务编号、当前状态、提交时间和对应后续操作。

表单保留上一步内容；提交后按业务类型提供“查看详情、继续新增、下载错误报告、返回列表”等操作。

所有二级页采用统一的全屏或抽屉式容器，通过标题、面包屑和返回按钮维持上下文。列表操作改变内存中的演示状态并展示明确结果；文件上传只演示选择、校验和导入结果，不向外部传输。

## 交互原则

- 商品卡片点击进入详情，“+”仍执行加入采购车。
- 方案卡片进入详情，支持直接购买；方案对比展示三套方案的关键差异。
- 表单必须可填写、保存并反馈状态；危险或不可逆操作不进入 Demo。
- 管理端菜单切换真实内容区域，待办记录可进入相应业务详情。
- 二级页在窄窗口下允许纵向滚动，关键操作始终可见。

## 验证

- 单元测试覆盖页面注册、默认页面和未知页面回退。
- 生产构建无错误。
- 浏览器逐条验证门户详情、企业表单、管理菜单和返回路径。
